Anatomy of the Composite Score

Every (model, iteration) pair is reduced to one number between 0 and 1, and the run with the highest number is called best. The whole calculation is two nested averages with a normalisation step in front — no weights are fitted, nothing is learned from the data. This traces it end to end on the real numbers.

composite = Σp wp · mean( score(c) for c in pillar p ) ⁄ Σp wp   with all wp = 1.0

The shape of it

Five stages, one number

The score is a funnel. Sixty measured columns are narrowed to twenty scoring components, each mapped onto a 0–1 scale; those are averaged within four pillars, and the pillars are averaged into the composite. Two further passes never touch the composite — they test whether the ranking would survive different weights.

Stage 1

Two ways a raw value becomes a score

Every component must land on 0–1 before it can be averaged with the others, and there are exactly two ways that happens. Which one applies is a deliberate, per-component choice, marked abs or rel in the code.

The distinction matters for reading results across stories: an abs score means the same thing next month, while a rel score is defined only against the eleven other runs it was computed with.

The pillar sizes are unequal, so the components are too

Each pillar contributes exactly a quarter of the composite regardless of how many components it holds. A pillar with three components therefore gives each of them 8.33% of the final score; a pillar with seven gives each 3.57% — a 2.3× difference in leverage that comes from nothing but how the components were grouped. Moving e2e infra failures from 0 to 1 shifts the composite more than doubling green share gained does. If that is not what you want, the fix is to change PILLAR_WEIGHTS or rebalance the groups, not the normalisation.

Stage 3

Two averages, and the winner falls out

Once every component is a number between 0 and 1, the rest is arithmetic. Nothing is weighted inside a pillar; nothing is weighted between pillars.

Stage 4

Would a different weighting change the winner?

Equal pillar weights are a choice, not a fact, so the notebook tests the ordering against every other reasonable choice. A run is Pareto-optimal when no other run beats or matches it on all four pillars at once — only such runs can ever place first under any positive weighting. Three of the twelve qualify.

“Pareto-optimal” is a much weaker guarantee than it sounds

It says only that some weighting exists under which the run wins — possibly an absurd one. Kimi it 2 needs 97% of the weight on tests & coverage, with the remaining 3% split across build, quality and behaviour, before it overtakes qwen it 3. That is why the notebook also reports top1_share: the fraction of 455 sensible weightings under which a run actually places first. Kimi it 2’s is 0.000.

Stage 5

How much the ranking really moves

The grid sweeps every combination of the four pillar weights from 0.10 to 0.70 in 0.05 steps that sums to 1.0 — 455 weightings. Each is scored, each produces a full ranking, and the notebook records the best and worst rank each run ever reaches.

Reading it

What the number does and does not say

  • It is a within-cohort comparison, not a grade. Eight of twenty components are min–max scaled against the other eleven runs. A composite of 0.836 does not mean “83.6% good”; it means “best of these twelve, by this weighting”.
  • Adding or removing a run changes everyone’s score. Any new iteration that sets a new cohort min or max rescales every rel component for every run. Scores are only comparable within one execution of the notebook.
  • Missing evidence scores zero, not neutral. A run with no e2e results loses its whole behaviour pillar — a quarter of the composite — which reads identically to a run that tried and failed. Check evidence_completeness in the integrity gate before trusting a low score.
  • Nothing self-reported is scored. Every component traces to a build log, a .trx, a Cobertura report, a metrics snapshot or an e2e probe result. The agent’s own claims are displayed beside the score, never inside it.
  • The gaps at the top are small. Rank 1 to rank 2 is 0.047; rank 2 to rank 3 is 0.034. With eight components rescaled per cohort, differences of that size are not a reliable basis for declaring one iteration better than another — the rank range in stage 5 is the honest read.

If you want to change what “best” means

Edit PILLAR_WEIGHTS in the ranking cell — it is a plain dict, and the grid and Pareto machinery adapt to whatever pillars exist. To change what counts rather than how much it counts, edit the PILLARS dict: each entry is (label, "abs" | "rel", series), and a label ending in ↓ is automatically inverted. Keep pillars similar in size, or accept the leverage asymmetry from stage 2.
